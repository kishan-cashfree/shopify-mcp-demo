# OCC spike — 2026-08-12

Two questions the milestone A plan is built on. Run against Cashfree sandbox.

## 1. Are the `one_click_checkout` feature flags required?

**No — but we keep them.**

Two orders were created against the same account, identical except for
`products.one_click_checkout`. The address endpoint was then called with each
resulting `payment_session_id` as `x-chxs-id`:

| Order | `GET …/customers/addresses` |
|---|---|
| **with** `checkoutCollectAddress` + `checkoutAuthenticate` | 200, 2 addresses |
| **without** any `products` block | 200, 2 addresses |

So the OCC endpoints do not gate on the flags. The concern that prompted this —
that Cashfree's own UI might re-ask for auth and address after we collect them —
does not apply on our path: the per-method tools (`UpiTool`,
`CardPaymentTool`, `NetbankingTool`, `NewCardPaymentTool`) render payment only.

**Decision, revised 2026-08-12 after the first live run: drop the flags.**

The original decision was to keep them, on the reasoning that the CheckoutTool
fallback opens the hosted OCC page and needs them. That reasoning inverted once
payment moved to opening Cashfree hosted checkout directly: the widget already
collects the phone, verifies the OTP and picks the address, so an OCC-enabled
hosted page offers to do all three again and the buyer logs in twice.

Re-verified on a live order created with no `products` block:

| Check | Result |
|---|---|
| Hosted checkout page loads | 200, "Cashfree Online Payments" |
| `GET …/customers/addresses` with that session | 200, 2 addresses |

So dropping the flags costs nothing we use and removes the double login.

No SMS was needed: an `authentication_token` captured earlier in the day was
still valid and was reused against freshly created sessions.

## 2. Which payment tools dispatch via `callTool`?

**Outstanding.** Cannot be settled with curl — it needs a real MCP host.
Measured in Task 12 Step 3 and recorded here.

The fallback is already designed and does not depend on the answer:
`callTool` → `sendFollowUpMessage` → hosted checkout. If most tools are
refused, the method list shrinks to those that work and hosted checkout is
promoted from escape hatch to primary.
